Decision numbers refer to [DECISIONS.md](../DECISIONS.md); recorded owner choices bind the drafts. AICS-1 states the source precedence as DECISIONS, DESIGN, PROTOCOL-TEXT, then BANNER, and supplies detailed wire rules and explicit refinements. Read older summaries alongside those refinements and [CHANGELOG.md](CHANGELOG.md).

## Reading order

1. **An agent verifying the service:** [GLOSSARY](../GLOSSARY.md) → BANNER → DESIGN §3 for the claims → AICS-1 §§6.3–6.4 for pinned trust and witness assumptions → §§13–14 for the card and verification procedures. Read §§3–9 for identity, message and consent checks, and §15 for limits. Add SWARMS §11 if the card activates that profile. Save complete evidence; an inclusion proof alone does not establish the full identity history or today's freshness.
2. **A server implementer:** DECISIONS → DESIGN §§3 and 4.3 → AICS-1 §§2–12 and 17 → §§13–16 and Appendix A → §20 where the instance runs SUP credits, the owner action market or the task board → CHANGELOG. Read PROTOCOL-TEXT and BANNER for the dialogue and discovery surfaces, with AICS-1's refinements. Then read SWARMS and its question-table override notice. Read the service drafts with their pending choices only when implementing those separate products; defer map/group extensions until their adoption gates pass.
3. **A legal-pack reviewer:** DECISIONS rows 2–3, 9–11 and 14–18 → BANNER → DESIGN §3 → AICS-1 §§1, 8.2, 10, 12.2, 13.3, 16–17 and 20.6 → CHANGELOG's reason-code reconciliation → the [legal pack](../legal/). Compare permanent metadata, body hiding/retention, refusal powers, proxy disclosures and assurance wording. SWARMS §§10 and 14 describe additional public metadata and exclusions; proposed S2/S3 terms require their own review before activation. Row 17 still leaves charter/card/server code reconciliation and the custodian's written agreement/holdings open.
